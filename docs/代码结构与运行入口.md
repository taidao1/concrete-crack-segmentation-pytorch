# 代码结构与运行入口

项目由 `crackseg/` 可复用模块和 `scripts/` 运行入口组成。结果概览见 [README](../README.md)，安装步骤见[环境与复现说明](环境与复现说明.md)。以下命令均在项目根目录、已激活的环境中执行。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `crackseg/paths.py` | 根据模块位置定位项目根目录、数据和输出目录 |
| `crackseg/data.py` | 配对读取、EXIF校正、标签二值化、RGB归一化与标准化、同步裁剪、Dataset |
| `crackseg/loaders.py` | 原图编号划分、Dataset和DataLoader组装 |
| `crackseg/models.py` | 创建SMP U-Net / ResNet34 |
| `crackseg/metrics.py` | 二值mask的像素TP / FP / FN计数 |
| `crackseg/engine.py` | 单轮训练、固定裁剪验证、整图评价及BN运行统计控制 |
| `crackseg/inference.py` | 滑窗坐标、分数融合、原尺寸mask、图片级存在性判断 |
| `crackseg/checkpoints.py` | 模型、优化器与历史保存恢复，以及仅模型权重加载 |
| `crackseg/visualization.py` | 显示原图、真实标注和预测对照 |

## 单图预测

```powershell
python -m scripts.predict --image "data/raw/metu_v1/rgb/582.JPG" --model "outputs/run_20261024_181934_060182/crack_segmentation_model.pth"
```

`--image` 接收照片文件，`--model` 接收模型权重文件，两项均必填。程序显示原图与预测mask，关闭图窗后打印有无裂缝的辅助判断。只需照片和模型权重，不需要真实标注、优化器或训练历史。

输入高、宽均须至少512。当前入口没有通用文件导出或目录批量预测参数；CUDA路径已运行，CPU回退分支尚未单独验收。权重目前没有公开下载链接，示例路径指向本地检查点。

## 整图评价

```powershell
python -m scripts.evaluate --split val --model-dir "outputs/run_20261024_181934_060182"
python -m scripts.evaluate --split test --model-dir "outputs/run_20261024_181934_060182"
```

默认 `--split val`；`val` 和 `test` 分别读取 `data/val_ids.txt`、`data/test_ids.txt`。`--model-dir` 接收包含 `crack_segmentation_model.pth` 的目录，默认使用上述epoch20目录。入口显式使用CUDA，累计整套原图的像素计数后输出全局IoU、Precision、Recall、F1及图片级统计。完整规则见[评价方法](评价方法.md)。

该版本的保留测试集评价已经完成；测试结果用于报告冻结方案的表现，不再用于选择权重或阈值。

## 首次训练与续训

```powershell
python -m scripts.train
python -m scripts.resume
```

| 入口 | 默认配置 |
| --- | --- |
| `scripts.train` | ImageNet预训练编码器初始化，20轮，Adam学习率1e-4，不固定BN统计 |
| `scripts.resume` | 从 `outputs/run_20261024_174146_218961` 的epoch17恢复，继续5轮；加载优化器后将学习率设为3e-5，固定BN运行统计 |

训练使用batch size 2和配对随机512×512裁剪。固定BN统计时，BN的可学习weight / bias继续更新。恢复目录由 `scripts/resume.py` 内的 `load_path` 指定，不会自动选择最新权重；这两个入口使用脚本内配置，没有训练配置命令行参数。

每轮包含固定裁剪验证和68张整图验证，以整图验证IoU改善作为保存条件。检查点写入 `outputs/run_<时间戳>/`，包含模型、优化器和JSON格式的 `stats.txt`。训练和恢复代码依赖CUDA，恢复时未还原全部随机状态。

训练入口扫描原图、按seed=1重建划分，应核对生成结果与仓库中的三份编号清单一致；评价入口直接读取清单。数据组织见[数据说明](数据说明.md)。

## 辅助入口

```powershell
python -m scripts.inspect_crops
python -m scripts.check_environment
python -m scripts.check_external_presence
```

| 入口 | 行为与范围 |
| --- | --- |
| `inspect_crops` | 默认加载epoch20，评价训练/验证的固定512裁剪，并显示首个真值有前景的验证样例；这些局部指标与整图指标分开解释 |
| `check_environment` | 输出解释器、依赖及CUDA状态，执行微型卷积前向、反向和参数更新；可用 `--output` 保存JSON |
| `check_external_presence` | 读取[三张外部照片来源清单](../reports/evaluation/external_presence_smoke/sources.json)，用CUDA和epoch20权重运行判断，写入 `outputs/external_presence_check/`；需另行准备清单中的本地照片 |

三张照片辅助检查与[六张外部照片试用报告](../reports/evaluation/external_presence_fresh_v1/report.md)是不同批次。
